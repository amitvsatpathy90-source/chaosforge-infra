## ADR-0404 — One shared lab JWKS stub in `foundation/` for both systems

**Status:** ACCEPTED

### Context
Both `rpe/secrets.tf` and `chaosforge/secrets.tf` set their JWKS parameters to `" "` (a single
space, because SSM rejects `""`), intending "unset, fail closed" — mirroring RPE's own
`29-oauth-config.yaml` (`issuer: ""`). That is not what it does. Every resource-server decoder in
both systems is built with `NimbusJwtDecoder`/`NimbusReactiveJwtDecoder.withJwkSetUri(...)`, whose
builder opens with `Assert.hasText`, and Spring documents `StringUtils.hasText(" ") == false`. So
the space threw `IllegalArgumentException` at decoder-bean construction and six app services
(RPE detection/relay/alert/triage; chaosforge edge-gateway/control-plane) crashlooped at boot — the
system under test was simply down, not fail-closed. No test caught it: the decoder bean is gated
`@ConditionalOnWebApplication(REACTIVE)` and the suites boot `webEnvironment = NONE`. Both systems
already ship their own nginx JWKS stub for local compose (`revenue-protection-engine/deploy/oauth/`,
`chaosforge/docker/jwks/`); the AWS deployment had no equivalent. The fix had to honour three
existing constraints: idle cost ≈ $0 (cost-model.md), zero `application*.yml` changes
(LOCAL-PARITY.md), and the one-way `foundation → child` state-read direction (ADR-0401).

### Decision
Deploy one nginx Fargate task in `foundation/` serving a single merged JWK Set — RPE's `rpe-lab-1`
and chaosforge's `chaosforge-lab-1` public keys, each decoder selecting its own by `kid` — at
`jwks-stub.observability.internal`, with `jwks_stub_desired_count` defaulting to `0`. Each child
root points its JWKS SSM parameter at that URL and declares its own egress rule to the stub's
security group in its own state, preserving the one-way dependency. Issuer and audience stay
byte-identical to local compose, because they are opaque exact-match strings that are never
dereferenced — only the JWKS URI is fetched — so the URI is the single value that drifts from
local.

### Alternatives Considered
- **Keep `" "` / leave the parameters blank** — rejected: it is the bug. It crashloops all six
  services at bean construction rather than producing the intended fail-closed 401.
- **A stub per system (two nginx tasks)** — rejected: duplicates a Fargate task, an ECR repo, and a
  Cloud Map registration to serve two static files, when a JWK Set holds many keys and each
  system's decoder already selects its own by `kid`. One set serves both.
- **A real IdP now (Cognito or Keycloak-on-Fargate)** — rejected for the first move: hours of setup
  plus standing cost/attack surface for a lab posture that ADR-19 (RPE repo) already sanctions a
  static JWKS for. Left as the documented upgrade path — it is a change of two SSM values and this
  file.
- **Bake the JWK Set into each app image** — rejected: couples key rotation to an app rebuild and
  would push a change into both app repos, breaking the "zero `application*.yml` change / additive
  only" local-parity contract.

### Consequences
**Positive:**
- All six app services boot, and token validation succeeds, when the stub runs — the RPE and
  chaosforge app tiers are startable at all for the first time.
- Idle cost ≈ $0 (`desired_count = 0`, same as every other service); one shared derived image on
  the existing ~$1/mo ECR line; no NAT, no ALB, no public IP.
- Degrades robustly: with the URL valid but the stub scaled to 0, decoders still build (lazy
  `RemoteJWKSet` fetch), services boot, and every token 401s — the fail-closed posture the `" "`
  value was mistakenly believed to give, now reached correctly.
- Local parity preserved: zero `application*.yml` changes; issuer/audience unchanged; the JWKS URL
  is the only tracked drift point (LOCAL-PARITY.md).

**Negative:**
- A third operator knob (`jwks_stub_desired_count`) that must be raised to `1` for token validation
  to actually succeed (live sessions, Prometheus scrapes) — easy to forget, and its absence
  surfaces as "everything 401s" rather than a hard error.
- Not a real IdP: no key rotation, no user model, static keys shared with the local lab and living
  in each repo's git-ignored directory, merged into the image at build time by
  `jwks-stub/build-push.sh` (which must be re-run when either repo regenerates its keys).
- Shared blast radius: the stub down blocks token validation for **both** systems at once (each
  still fails closed independently, so it degrades rather than errors).
- Runtime-unverified: validated, `fmt`-clean, and R1-policy-gated offline, and the two-key merge is
  tested against the real key material — but no `terraform apply` has run, so "all six boot healthy"
  remains unproven until one does, in common with the rest of this repo.
