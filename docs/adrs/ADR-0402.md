## ADR-0402 — NAT Gateway as an opt-in, triage-scoped egress path

**Status:** ACCEPTED

### Context
Module 2 chose no NAT Gateway on cost grounds. Module 4 reversed that: the data-layer containers
(Postgres/Redis/Redpanda) pull public Docker Hub/Quay images, and there is no PrivateLink endpoint
for either registry, so a NAT Gateway was added to make those pulls possible. Once ECR mirrors
existed for those same images (removing the one-time push step), the only remaining NAT consumer
became `rpe-triage-agent`'s call to OpenAI's hosted API (`spring.ai.openai`, `gpt-4o-mini`) — and
triage already has a documented degraded mode (ADR-15 §9: `DEGRADED_RULE_BASED` verdicts) for when
the LLM is unreachable.

### Decision
`enable_nat_gateway` (`foundation/network.tf`) defaults to `false` — Module 4's NAT justification
is stale now that ECR mirrors cover the data-layer image pulls it was added for. NAT stays
available as a session-scoped opt-in, and when enabled, `rpe/security-groups.tf`'s
`triage_to_internet_https` egress rule scopes actual internet access to the `triage` security
group alone — no other RPE service gets general internet egress regardless of the NAT flag.

### Alternatives Considered
- **Keep Module 4's NAT-always-on posture** — rejected: its justification (data-layer images with
  no PrivateLink path) no longer applies once ECR mirrors exist for those same images; leaving NAT
  on by default would charge ~$36/mo (NAT + its public IPv4) for egress capacity nothing needs by
  default.
- **Drop NAT entirely (Module 2's original stance)** — rejected: `rpe-triage-agent` has a genuine
  use case for real internet egress (OpenAI has no PrivateLink endpoint), so the capability still
  needed a path to exist, even if off by default.

### Consequences
**Positive:**
- Idle cost stays near $0 (NAT is the default-off case), while a working path to real,
  LLM-backed triage verdicts exists for any session that explicitly opts in
  (`enable_nat_gateway = true` + a real `openai_api_key`).

**Negative:**
- Enabling NAT for a triage session pays for the whole VPC's NAT egress capability (~$0.05/hr per
  the cost model), not a triage-only charge — the security-group rule scopes *which service* can
  use the path, not what the NAT itself costs while provisioned.
